## 1. 一句话现状

「录制 → 转写 → 说话人分离 → 纪要」这条链**已经用真实中文音频端到端跑通并有实测数据**；
桌面应用编译得出安装包、能启动，但**没有任何一个按钮被人点过**。

接手后的第一件事是 §8 的验收清单，不是写新功能。

  models.rs     455   权重路径解析、SHA256 校验、一键下载与解压        §6

  jobs.rs       122   任务状态机与进度加权
  error.rs       81   错误分类（策略拒绝 vs 网络故障要分开）

crates/capture/src/lib.rs   Windows WASAPI 双轨采集                §4.1
crates/cli/src/main.rs      11 个子命令，兼作 W1 评测载体

**两个刻意的设计**，改动前请先理解：

1. **`TranscriptionEngine` trait**（`asr.rs`）——换 ASR 模型时上层零改动。这是 §8.2 许可证风险的兜底，不要图省事绕过它直接调 sherpa。
2. **出网守卫**（`policy.rs`）——所有对外请求必须经 `LlmClient::guard()`。绕过它加一个 HTTP 调用，等于把 §5 的隐私边界打穿。

## 4. 从零把它跑起来

```bash
# 前置：Windows 10/11、Rust stable (MSVC)、Node 22+、约 6G 磁盘
bash scripts/fetch-models.sh models        # 下载 ONNX 权重，解压后约 357MB
npm install
cargo build --release -p vocmeet-cli       # CLI
npx tauri build                            # 桌面应用 + 安装包
```

产物统一在 `target/release/`：

- `vocmeet-app.exe` / `vocmeet-cli.exe`
- `bundle/msi/VocMeet_0.1.0_x64_en-US.msi`（14.0 MB）
- `bundle/nsis/VocMeet_0.1.0_x64-setup.exe`（9.8 MB）

**安装包不含权重**（357MB），装完仍需跑 `fetch-models.sh`，并在设置页把模型目录指过去。

纪要生成需要本地 Ollama：`ollama serve && ollama pull qwen2.5:7b`。
没有它的话，录制、转写、逐字稿、导出都正常，只是没有纪要与关键词。

CLI 与 GUI **共用同一个数据库**，可以互相验证。

## 5. 有数据的部分，和仍然空白的部分

### 已实测（本机单样本，sherpa-onnx 官方四人中文音频 56.9 秒）

| 指标 | 实测 | 方案目标 |
| :--- | :--- | :--- |
| RTF | **0.096** | ≤ 0.15 ✓ |
| 双轨时长对齐误差 | **74 ms** | < 200 ms ✓ |
| 已知人数时说话人数 | **4，准确** | — |
| 未知人数时说话人数 | **6，过分裂** | ≥80% 准确 ✗ |

### 仍然是空白

**CER 与 DER 没有任何数据。** 算它们需要人工转写并标注说话人边界的 golden 数据，
即方案 §7 的 Set-A 测试集——**这件事还没开始**，是 W1 的第一优先级。

在拿到 CER/DER 之前，「高转写准确率」这个产品主张是**未经证实**的。
方案 §7 指标表里除上面四行外全是目标值，对外材料里不要引用。

### 长会议的新数据（2026-09-10 补测，导入的 85 分 33 秒真实会议）

| 指标 | 实测 |
| :--- | :--- |
| 解码 .aac → 16k WAV | 1.0s |
| 识别 + 分离 + 标点 | 约 20 分钟（num_threads=2） |
| 产出 | 387 条发言，中文识别质量可用 |
| **未传人数时的说话人标签** | **217 个** |

两条结论，都比 56.9 秒样本上看到的严重：

1. **聚类阈值在长音频上彻底失效。** 四人样本是「4 切成 6」，这里是 387 条发言切出 217 个标签——
   同一个人在不同段落被判成不同的人。阈值标定不再是「调优」，是**长会议可用性的前提**。
2. **耗时远差于 RTF 推算。** 按 0.096 推算应是 8 分钟，实际约 20 分钟。瓶颈在 diarization，
   开销随片段数超线性增长，短样本上量不出来。§7 的 RTF 指标必须在长音频上重测。

### 一条值得记住的实测结论

不传参会人数时，4 人音频被聚类成 **6 个**说话人标签；传 `--speakers 4` 则精确得到 4 个。
说明**默认聚类阈值 0.5 偏低会过分裂**。这条实证了 §4.2「已知人数走 num_clusters 更准」的
设计判断，也说明用户没填参会名单时分离质量目前不可用——阈值标定必须在 W1 做。

## 6. 与方案的五处偏差

都是实现期被现实逼出来的，不是设计变更，接手后需要自己判断是否回补。

### 6.1 SQLCipher → SQLite + 字段级 AEAD（安全性实质降级）

`rusqlite` 的 `bundled-sqlcipher-vendored-openssl` 要从源码编译 OpenSSL，
本机 Windows 工具链缺 Perl 模块 `Locale::Maketext::Simple`，构建失败。

改为对敏感列做 AES-256-GCM，密钥仍在 Windows 凭据管理器。

- 仍加密：逐字稿正文、随手记、纪要正文
- **不再加密**：表结构、时间戳、说话人 key、会议标题

MVP 内部试用可接受，**v1.0 必须改回整库加密**。见 `crates/core/src/store.rs` 顶部注释。

### 6.2 rubato 5.0 → 0.16

rubato 5.0 换成基于 `audioadapter` 的新 API，`SincFixedIn` 已移除。锁 0.16.x。
方案 §3 表里写的 5.0.0 是核实当时的最新版，但不适用。

### 6.3 音频解码引入 symphonia（方案未提及）

方案里没有「导入已有音频」这条路径，`audio.rs` 原先只有 hound，即只认 WAV。
支持拖入 `.aac` / `.m4a` / `.mp3` 需要一个解码器：

- 选 `symphonia`（纯 Rust，静态链接，无 ffmpeg 依赖），不选 shell 调 ffmpeg——
  后者会把「离线、自包含」这个产品前提打一个洞（用户机器上未必有，安装包也不该塞一个 ffmpeg）。
- 许可证是 **MPL-2.0**，文件级弱著佐权，链接进 Apache-2.0 应用无额外义务。见 README「许可证注意」。
- 打开了 `all-codecs` + `all-formats`，可导入清单是 `audio::IMPORTABLE_EXTENSIONS`，
  **这份清单必须与 feature 开关一致**：列了但解不了，用户看到的是「导入失败」而不是「不支持」。

`resample()` 那个「chunk 取整段长度」的写法在导入场景下会吃掉 GB 级内存，
所以另写了一个私有的 `StreamResampler` 跨块复用同一个 rubato 实例（滤波器状态连续，块边界无断点）。
两条路径并存：录制走原来的整段版，导入走流式版。

### 6.4 一键下载权重（方案 §6 只写了「首次启动校验」）

方案假设权重由脚本准备好。实际上装完安装包的用户手上没有 bash，也不该去开命令行，
所以补了应用内下载：`models::fetch_all` 走 reqwest 流式下载 → `bzip2-rs` + `tar` 纯 Rust 解压
→ 比对 `EXPECTED_SHA256` → 写回配置。全程 265MB，本机实测 38.5 秒。

**这条路径刻意不经出网守卫**（`policy::check_endpoint`）。守卫管的是「用户数据出本机」（§5），
而下载是纯下行：请求体是空的，不含任何会议内容。用户点「一键下载」这个动作本身就是授权。
理由写在 `fetch_all` 的文档注释里，改动前先读那段。

`EXPECTED_SHA256` 取自本机跑通全链路的那一套权重。上游 release 是带日期的固定 tag，
不会原地更新；对不上就是下载损坏或上游被动过手脚，两种都该拦。

### 6.5 PDF 导出走系统打印

`window.print()` + 打印样式（自动隐藏侧栏、播放条、折叠区），用「Microsoft Print to PDF」保存。
原生生成 PDF 要嵌 CJK 字体，体积与授权都不划算。Markdown 导出是原生的。

## 7. 已知的坑

接手时会撞上的，先写在这里省得重踩。

| 坑 | 说明 |
| :--- | :--- |
| **两个 target** | 已修。`src-tauri` 原先被 `exclude` 出工作区，成了独立 cargo 项目，依赖编译两遍。现已并入 `members`，产物统一在 `target/release/` |
| **权重不进版本库** | `models/` 583MB，靠 `fetch-models.sh` 拉。svn 忽略规则已设 |
| **asset 协议作用域** | 回放音轨要能被 webview 播放，`main()` 里只放开音频目录，没用通配符。改数据目录时要同步改 |
| **随手记的真源是数据库** | 组件本地 state 只是缓存。落盘格式 `[mm:ss] 内容`，切走再回来靠解析还原。改格式要同时改 `serialize`/`parse` 两处 |
| **纪要失败不回滚逐字稿** | 逐字稿本身有价值。`process_meeting` 里纪要与关键词失败都只记 warn |
| **CJK 字符串处理** | 截断一律用 `chars().take(n)` 不要用字节切片；文本拼接见 `align.rs::join_text`（中文之间不插空格） |
| **Tauri ACL 权限文件** | 已补。此前仓库里**没有 `src-tauri/capabilities/`**，Tauri v2 的 ACL 默认不授予任何插件权限——`listen()`（全部进度事件）与文件保存框在运行时都会被拒。这解释了「编译通过但交互零验证」下潜伏的一类失败。现在 `capabilities/default.json` 授予 `core:default` + `dialog:allow-open` / `allow-save`。**加新的插件调用时要同步加权限**，否则只在运行时报错 |
| **release 必须开 `custom-protocol`** | 直接 `cargo build --release -p vocmeet-app` 出来的二进制**仍然指向 devUrl**，打开是 `ERR_CONNECTION_REFUSED`（localhost:1420 没人应答），而不是加载内嵌的 `dist/`。要么 `npx tauri build`（推荐，它会自己带上），要么 `cargo build --release --features custom-protocol`。进程活着 ≠ 页面渲染出来了，冒烟测试要看窗口内容 |
| **配置里的路径必须是绝对的** | 已修，但值得记住这个教训。`models_dir` / `templates_dir` / 配置文件本身原先都是相对路径（`"models"`、`"templates"`、`"vocmeet.config.json"`），相对路径的基准是**进程工作目录**——开发时是仓库根，装完之后是快捷方式指向的任意目录。表现为「模型明明在盘上，应用却报 not found」，而且配置永远存不下来（Program Files 无写权限）。现在配置固定在 `%LOCALAPPDATA%\VocMeet`，`Config::load` 会 `absolutize()`，启动时 `adopt_existing_models()` 认领可执行文件旁边或工作目录下已有的权重。**新增任何路径配置项都要走同一条路** |
| **模板随包分发** | `templates/meeting_default.yaml` 现在是 Tauri resource。注意 `resources` 用的是**映射形式**而不是 glob：写 `"../templates/*"` 会被塞进 `_up_/templates/`，路径不稳定；映射形式 `{"../templates/x": "templates/x"}` 才落在 `resource_dir()/templates/` |
| **两份模型清单** | `scripts/fetch-models.sh` 和 `models.rs::ASSETS` 各有一份，必须一致。有个单元测试（`assets_stay_in_sync_with_the_fetch_script`）读脚本比对文件名，改一处忘另一处会挂 |
| **导入音频是流式解码** | `audio.rs::transcode_to_wav` 边解边写，不整段进内存。改它时别图省事先 `read_wav` 再 `resample`——一小时 48k 立体声是 GB 级 |

## 8. 验收清单（接手第一件事）

装 `VocMeet_0.1.0_x64-setup.exe`，逐项确认。**每一项都没被验证过。**

**基础**
- [ ] 设置页三行自检全绿（模型 / 数据库与凭据 / 系统回环）
- [ ] 设置项修改后失焦即保存，重启应用后仍在

**录制**
- [ ] 输入标题 → 开始录制 → 波形动、计时走
- [ ] 录制中「新建会议」入口置灰
- [ ] 记 3 笔，气泡按时间戳堆叠
- [ ] 连记 15 笔，**笔记区高度不变**，只在气泡列表内部滚动，输入框不动
- [ ] 窗口拉到最小（960×640），标题/波形/计时/结束按钮都不被裁

**随手记持久化（重点，之前修过一次 bug）**
- [ ] 记 2 笔 → 切到设置 → 切回来，**气泡还在**
- [ ] 记 2 笔 → 切到别的会议 → 切回来，**气泡还在**
- [ ] 会议结束后，已完成会议页能看到「随手记」区

**录制置顶条**
- [ ] 录制中切到别的会议或设置，底部出现反色置顶条，红点闪烁、整条呼吸
- [ ] 点击置顶条回到录制界面

**结束与整理**
- [ ] 点「结束会议」直接进整理界面，**不出现「排队中」字样**
- [ ] 整理完成后侧栏状态变化，进入会议能看到内容

**已完成会议**
- [ ] 播放条能播、能拖动、时间显示正确
- [ ] 关键词与参会人显示（关键词需要 Ollama）
- [ ] 纪要正文可读
- [ ] 另存为 Markdown 落盘正确
- [ ] 另存为 PDF 弹出打印对话框，且**只有纪要，没有侧栏**
- [ ] 展开逐字稿，命名说话人后真名回填

**分页**
- [ ] 造 25 场以上会议，侧栏显示「加载更多」并能翻页

**导入音频**（新增，同样一次都没被人点过）
- [ ] 把一个 `.aac` 拖进窗口任意位置，整屏出现虚线框与「松手，把这段音频变成一场会议」
- [ ] 松手后直接进整理界面，先显示「正在解析音频」和解码进度，再转到「整理逐字稿」
- [ ] 会议标题默认取文件名（不含扩展名）
- [ ] 整理完成后，已完成会议页的播放条能播这段导入的音频
- [ ] 拖一个 `.txt` 进来，报「这不是能识别的音频」，不新建会议
- [ ] 一次拖两个音频，只处理第一个并给出提示
- [ ] 录制中拖入音频，报「正在录制，先结束当前会议再导入」
- [ ] 录制页点「选个文件」，文件框的格式过滤有内容（这条同时验证 `dialog:allow-open` 权限）

**首次配置**（新增）
- [ ] 把 `models_dir` 指到一个空目录，设置页「识别模型」显示「缺失」并出现「一键下载模型」
- [ ] 点下载，进度条按资产推进，阶段文字在「下载中 / 解压中 / 校验中」之间切换
- [ ] 下完自动变「就绪」，`vocmeet.config.json` 里的 `models_dir` 已经指到新位置
- [ ] 下载途中点「取消下载」，不留半截文件，再点一次能重来
- [ ] 「已经有了，指个目录」选一个有效目录能生效，选一个空目录会报缺哪个模型
- [ ] Ollama 没启动时，端点体检报「连不上」且给出 `ollama serve`
- [ ] Ollama 启动但没模型时，报「服务在跑，但一个模型都没装」并出现「拉取 qwen2.5:7b」
- [ ] 点拉取，进度跟着走，完成后「模型」字段自动切到拉下来的那个
- [ ] 模型输入框的下拉里，列的是端点上真实装着的模型

**重新整理**（新增）
- [ ] 已有纪要的会议，底部出现「重写纪要」与「重新解析录音」
- [ ] 点「重写纪要」，逐字稿条数不变，纪要内容刷新
- [ ] 改一个 LLM 模型再点一次，用的是新模型（看出网审计里的 model 字段）
- [ ] 点「重新解析录音」，先「重新识别」再「重写纪要」，完成后逐字稿条数可能变化
- [ ] 录音已被手动删掉的会议，只出现「重写纪要」，不出现「重新解析录音」
- [ ] 没有 LLM 时点「重写纪要」，报「纪要没写成」并说明原因，**逐字稿不受影响**
